## 前沿模型遥不可及

但有一个小问题，那就是语言模型的工业化已经发生了。前沿模型真的非常非常昂贵。三年前，GPT-4 据称训练成本是 1 亿美元。现在成本大概是十亿量级，虽然这是推测。所有大实验室正在构建的 GPU 数量简直是巨大的。而且，这些模型是如何构建的没有任何细节。即使在 2023 年，GPT-4 的论文明确说，由于竞争格局和安全方面的考虑，我们不会分享任何关于模型如何构建的内容。所以这些前沿模型在某种意义上是遥不可及的。

我们可以构建小语言模型，我们也会构建小语言模型。但是，我认为重要的是要记住，这些可能不能代表真正的前沿模型。我给你两个例子说明为什么可能是这样。

这里有一个帖子。这其实是相当久以前的，我想是 2021 年。我们后面会花更多时间在 FLOP 计数上，看看计算花在哪里。但如果你看小规模，花在 MLP 层中的 FLOPs 比例大约是 44%。如果你扩展到 175B，它就变成 80%。所以你在大规模上优化什么、什么重要，和在小规模上是不同的。所以如果你在这里的 attention 上做了一堆小规模的工作，你可能在大规模上看不到同样的收益。

第二个例子是我们知道随规模出现的涌现行为。小模型，这也是很久以前的，但即使在那时，如果你做各种任务的零样本或少样本学习，基本上看起来什么都没用。只有当达到临界规模时，你才突然看到很多改进。所以，如果你在小规模上工作，你可能看不到某些类型的现象，和在全规模上工作相比。

## 三类可迁移的知识

好，所以这可能有点令人沮丧。但别怕，我们在这门课上会学到东西。问题是，我们能学到什么真正可迁移的东西？

我觉得把它分解成三类知识很重要。第一，事物的机制（mechanics），transformer 是什么，模型并行是如何工作的。第二，心态（mindset），你如何着手构建一个语言模型。我们会讨论如何从硬件中榨取最大价值，认真对待 scaling。最后是直觉（intuitions），哪些数据建模决策会产生好的性能。

在这门课中，我觉得我们能很好地教授机制，也就是事物如何工作，以及心态。我们会非常强调你要 profile 和 benchmark 一切，并尝试优化效率。这些东西确实可以迁移到更大规模。关于哪些建模决策和数据决策有效的直觉，可能不一定能跨规模迁移。对于那个，你实际上必须去一个能做大规模事情的地方。

关于直觉这一点，值得说的是，有些设计决策就是无法证明的，纯粹来自实验。而机制，你可以从构造上看到并行化和 kernel 将如何加速等等。但关于哪些建模改变有效的直觉，我觉得你就必须跑实验。有一篇著名的 Noam Chomsky 的论文引入了 SwiGLU 激活函数，我们后面会看。在结论部分，他非常诚实地有最后这句话，说的是，我们不提供解释。我们将这些架构的成功，以及其他一切，归因于神的恩典。所以这在某种意义上是你只能从经验中获得的东西。

## Bitter Lesson 的正确解读

最后关于 bitter lesson 的一点，我觉得它一直在流传，人们在讨论。我觉得有一个常见的误解，关于它意味着什么。我觉得错误的解读是，规模就是一切，算法不重要。但那是不对的。正确的解读是，能 scale 的算法才是重要的。你可以很简单地想，你模型的准确率基本上就是你的效率乘以资源。效率是输出除以输入，资源是输入。而效率在更大规模上实际上在某种意义上是更重要的。对吧？如果你做小规模实验，如果你的运行花了两倍时间，也许你就多等两倍时间然后回来看。但如果你在大规模上做事，那可能是几亿美元。你肯定不想那样。即使 5% 的改进可能都是大事。所以实际上，效率是非常非常关键的。我希望把这一点作为这门课的结果之一烤进你们的心态里。

经验上，如果你看 OpenAI 2020 年的那篇论文，它显示 2012 到 2019 年间在 ImageNet 上有 44 倍的算法效率提升。当然硬件也变好了很多。但那也伴随着算法的改进。当然，当你把它们乘在一起时，你就会看到效率和准确率的巨大跃升。

所以有这些之后的框架是，在一定的数据和计算预算下，人们能构建的最好的模型是什么？对于预训练，我们主要会讨论计算预算，因为我们会尝试假设我们有的数据比计算多得多。但如果你处在一个数据受限的环境中，或者你藏了非常多的 B200，那你可能是数据受限的。换句话说，最大化效率。我们会在这门课中反复看到这个主题。

## 语言模型简史

好。接下来，我想花一点时间谈谈语言模型和一点历史，在跳进更技术性的细节之前做个背景铺垫。

语言模型已经存在一段时间了。Shannon 在 50 年代就在用语言模型来测量英语的熵。很长一段时间里，n-gram 模型实际上被用于机器翻译和语音识别系统。它们不是整个系统，但它们是确保你生成流畅文本的重要部分。

我想说现代语言模型的谱系来自神经架构。所以有一堆想法，我觉得对这个发展很重要。90 年代有 LSTM。Joshua Bengio 实际上在 2003 年写了第一篇神经语言模型论文。这其实不是 LSTM。这只是一个前馈网络，看一个小上下文。然后有序列到序列建模，大胆地说我们可以把整个句子压缩成一个向量。注意力机制，是为机器翻译开发的。Transformer 架构，建立在它之上，也是为机器翻译开发的。然后扩展到混合专家、模型并行。你会看到很多不同的架构，还有系统和优化器的想法。都在 2010 年代发展出来。

然后到 2010 年代末，我觉得事情开始变得非常有趣。有 ELMo 和 BERT。这些是在大量文本上训练的语言模型。然后你可以在一些下游任务比如问答上微调它们。它会显示巨大的改进。所以那里的模式是，拿一个这些模型然后微调。然后 Google 有一篇论文，我觉得真的预示了这种 prompt 和 response 的视角。

真正打开闸门的，我觉得是 OpenAI，通过拥抱 scaling。他们在 2018 年左右有一篇 GPT 论文。他们扩展到 GPT-2。然后他们真的弄清楚，或者拥抱了 scaling laws 的想法，我们一会儿会讨论，这让他们能够训练 GPT-3，那要大得多，比当时最大的模型大超过 10 倍。而且它能展示涌现行为，比如上下文学习。那时候，Google 就说，好，我们也得做点什么。所以他们训练了一个巨大的模型。结果它有点训练不足。结果他们的 DeepMind，当时还没和 Google 整合，已经弄清楚了最优的、计算最优的 scaling laws。所以所有这些都在发生。

GPT-3 出来之后，我觉得对很多人来说，这算是一个警钟。那时候有很多早期的尝试，让我们试着复制这个。有一个草根组织叫 Eleuther，创建了一些开源数据集和模型。它们不是很大，因为他们没有多少计算。Meta 的第一个 LLM，你能看出它是复制品，因为它是 1750 亿参数。但它不是一个很好的模型。他们遇到了很多硬件问题。然后还有一个 Hugging Face 的 BigScience 项目。所以这些模型，我想说，不是很强。

然后过去三年，我觉得开源模型生态变化很大。Meta 以 Llama 系列模型引领，Llama、Llama 2、Llama 3。Mistral 加入了游戏。然后一整套中国模型。我觉得我漏了一些，比如字节跳动有一些东西。我觉得腾讯可能也有一些别的东西。所以要跟踪所有东西很难。但所有人都听说过 DeepSeek 和 Qwen。所以我觉得我提到了主要的。但我觉得这些有趣和令人兴奋的是，现在我们有开放权重的模型正在接近闭源模型。取决于你问谁以及怎么 benchmark，它们可能稍微落后或者相当。但肯定有非常非常可信的模型被广泛用于工业界。

现在还有另一条工作线，超越了仅仅发布开放权重模型。AI2、NVIDIA，以及我参与的 Marin 项目。我们尝试不仅提供权重，还提供论文、代码和数据，这样我们可以更彻底地理解这些模型是如何构建的。我为什么这么强调开放生态？主要是因为这门课没有这些模型是不可能的。事实上仍然有很多论文在发表关于这些大的 MoE 和 RL 系统如何工作。让我们至少能窥见这些前沿模型是如何构建的，并尝试三角定位各个部分。当然即使有这些像 Qwen 论文，我觉得它们也漏掉了很多细节，所以你没法复现它们。特别是数据混合是我们不知道的。但我觉得这比什么都没有好得多。

## 语言模型定义的演变

好，所以过去十年，语言模型的概念变了。它曾经是你微调的东西。然后是你 prompt 的东西。现在在 ChatGPT 时代，它是你与之对话、可以交谈的东西。现在，好，我猜我没有网络。那没关系。现在我们处在智能体的时代。如果你点这个链接，它基本上给你展示一个巨大的智能体 trace。我仍然有点，这些模型有些有多强简直令人难以置信。你给它一页文本，它做一些非常复杂的智能体编码任务。所以，我们今天对语言模型的要求可能超出了十年前任何人的想象。

话虽如此，我觉得基础并没有改变那么多。我们仍然主要是在 GPU 和 kernel 上构建。我们仍然用梯度或随机梯度之类的方法优化。我们仍然有 transformer 和注意力，我们会多谈一点架构。但并没有改变那么多。我觉得规格不同了。现在我们要求更长的上下文长度，这意味着推理效率更加重要。所以对我们来说好消息是，我们不必完全改变这门课。只有 Tatsu 关于最新中国架构的那部分。但基础，我觉得会留下来，至少目前是这样。

### Scaling Laws：如何预测大规模训练的损失

好。第三个作业是关于 scaling laws。到现在，你已经训练了一个语言模型。你可以通过优化 kernel 和并行让它跑得很快。现在，你想 scale up。那你如何 scale up？

想象以下设置。如果你有 1e25 FLOPs，这是几千万美元的计算，你会训练什么模型？好。这是一个我觉得有点令人生畏的任务，因为如果你搞砸了，那是一大笔钱打水漂。而且你不能在那个规模做你通常的超参数调优，因为你只能训练一个模型。所以这是你在大语言模型训练中必须处理的关键问题，而你如果只是微调一个模型或做小规模的事情就真的不需要处理。所以这里关键的概念转变是，我们不应该想我们正在训练的一个单一模型，而应该想一个 scaling recipe。一个 scaling recipe 是从一个 FLOP 预算，比如 1e25 或 1e24，到一个超参数集合，基本上一个配置文件的映射。对于给定的 scaling recipe，我们要做的是跑一堆实验来计算你在更小规模下得到的损失。然后你拟合一个 scaling law，这让你能预测目标规模下的损失。所以也许你跑一些小实验，拟合 scaling law，然后预测更大规模下你会得到什么。

好。这就是原语。现在用这个，你可以做的是，你可以优化目标，scaling recipe，以更大规模为目标，用小规模实验，这很棒。第二，你可以在实际跑实验之前预测你理论上会达到的损失。这让你可以去，你知道，筹钱，你说，看，我跑了小规模实验，我觉得我能得到一个 GPT-5 级别的模型。请给我很多钱让我训练那个模型。

有一件事我觉得可能是另一个误解，就是 scaling laws 不是自然定律。它们不会自动发生。你得把它们祈愿出来。这通过仔细构建一个 scaling recipe 来实现。一个 scaling recipe，记住，它必须外推。所以这通常意味着你有一个超参数序列，说随着规模增加，也许学习率是常数，也许它下降，也许 batch size 增加，但增加多少？这些是 scaling recipe 必须弄清楚的事情。所以你参数化，然后为了得到这些可预测的 scaling laws，你实际上必须考虑的一件事是，你如何参数化模型来得到所谓的超参数迁移（hyperparameter transfer）。意思是你在小规模用的超参数要么是你在更大规模用的，要么是它的可预测函数。因为如果每个规模你的学习率有时是 1e-5 有时是 1e-4，那你不能神奇地在更大规模猜对学习率。所以一个思维转变是，可预测性实际上至少和最优性一样重要。你通常想，哦，我们试着优化效率，我们想超参数调优并让事情最优。是的，你确实想那样做，但你也想要这种可预测性，这样你不会在更大规模上被惊喜到。

好，这是舞台设置。我们要看的实际 scaling laws 相当经典。你们有些人可能见过这个想法，如果我给你一个 FLOP 计算预算，你应该如何平衡训练更大的模型和在更多 token 上训练？这就是经典的 Kaplan 等人的计算最优 scaling laws，以及所谓的 Chinchilla scaling laws 进来的地方。基本想法是，对每个 FLOP 计算预算，比如从 6E18 到 3E21，你扫不同的模型大小。你选最好的，想成最小化每一个。然后你拟合一条曲线，让你基本上能预测给定 FLOP 计算预算的参数数量。如果你幸运，它会大致落在一条线上。如果你不幸运，它会到处都是，这意味着你应该没有信心你能可靠地预测。所以，这个的结论是，这相当粗糙，但一个经验法则是，参数数量的 20 倍是你应该训练的数据点数量。所以这个 1B 参数模型应该在大约 1.4 万亿 token 上训练。当然，取决于数据集和架构，这个数字实际上会变。好，这也没有考虑推理成本。现在很多模型很小，但它们在比计算最优多得多的 token 上训练，因为你想要一个更小的模型用于推理。

好，我们在 Marin 项目一直在做的一件有趣的事是预注册我们的结果。我们拟合一堆 scaling 图在不同计算预算下。我们拟合一个 scaling law，然后我们基本上做这些预测到 1E22 flops。这个实际上在训练。如果你去 Marin 网站，你可以跟着看。它可能最早今晚就完成。所以也许周三我会报告我们做得怎么样，看看我们和预注册的损失匹配得如何。这里想法是，我们做了一个预测，如果我们要训练这个我们从未训练过的大模型，如果我们能预测它会做得多好，那就很好。

好，在作业三中，我觉得这有点有趣，或者，实际上是一个有趣的作业。我们就说它是个有趣的作业。我们要定义这个训练 API，基本上你给我们超参数，我们给你一个损失回来。我们要做的是模拟如果你能做很多训练运行会发生什么。当然我们没有足够的计算实际让每个人训练他们自己的，你知道，8B 模型之类的。所以我们基本上离线训练一堆模型，我们基本上提供这个缓存，这样看起来像你在训练。你要做的是提交训练任务。你给我们一个配置，基本上我们给你一个损失回来。然后你可以做任何你想做的。我们建议你拟合 scaling laws 到这些点，然后你外推，然后我们给你一个预算，我们基本上评估你的模型落点如何。所以它意在，我本来要说，它意在复制高压场景，如果你实际有一个预算，比如 1 亿美元，你必须花掉。你必须非常小心你如何花这个。当然这是低风险的。
